# 기계학습 실험 절차

현재는 주제와 데이터가 미정이다. 이 문서는 실험을 진행할 때 사용할 절차이며, 완료된 실험이나 성능을 나타내지 않는다. 공통 설정의 확정 값은 [CONTRACTS.md](CONTRACTS.md)에 기록한다.

## 1. 수업 요구사항 확인

[프로젝트 안내](https://github.com/2026-2nd/.github/blob/main/docs/프로젝트_안내.md)를 기준으로, 다음을 작업 계획에 반영한다. 확인 기준일은 2026-10-27이며 후속 공지가 우선한다.

- 전공과 연관된 지도학습 문제를 정의한다. 전처리 후 피처 10개 이상, 행 1,000개 이상을 충족하는지 확인한다.
- 비교할 기계학습 알고리즘은 2개 이상, 평가 지표는 문제에 맞게 2개 이상 선정한다.
- 모델마다 같은 학습·검증·테스트 분할과 같은 지표를 사용한다.
- EDA와 실험 해석을 뒷받침하는 그래프 8개 이상을 준비한다.
- 실행 방법·환경·출처·전처리·결과 해석·한계를 기록한다. 딥러닝은 선택 사항이다.

안내의 일부 날짜는 서로 맞지 않는다. 마감일·제출 방식은 최신 공지를 확인해 별도로 정한다.

## 2. 문제와 데이터 정의

예측 단위가 무엇인지, 언제 예측하는지, 정답을 어떻게 만드는지 먼저 정한다. 입력에 예측 시점 이후의 정보나 정답을 사실상 알려 주는 변수가 포함되지 않는지 확인한다.

데이터셋 이름·출처 URL·다운로드 날짜·버전/해시·라이선스·재배포 조건을 기록한다. 개인정보·민감 정보 포함 여부와 수업 사용 조건을 확인한다. 공개 데이터라는 이유만으로 재배포가 허용된다고 가정하지 않는다.

행의 단위, ID, 컬럼 자료형, 타깃 정의, 결측·중복·클래스 분포를 확인한다. 제외 규칙과 전처리 전후 행·피처 수를 기록한다. 원본은 보존하고 변경은 코드로 재현한다.

## 3. 분할과 데이터 누수 방지

- 독립된 표본이면 문제에 맞는 무작위 분할을 검토한다. 분류에서 표본 수가 허용하면 클래스 분포를 고려한다.
- 같은 사람·기기·장소 등 그룹에 속한 행은 그룹이 섞여 점수가 부풀지 않도록 분리한다. 시간 순서가 있는 예측은 미래 데이터로 과거를 학습하지 않도록 한다.
- 분할 비율, 기준, seed, 원본 버전과 행 ID를 기록한다. 같은 seed라도 입력 행 순서가 바뀌면 분할이 달라질 수 있으므로 ID 또는 재생성 가능한 분할 정의를 함께 보존한다.
- 결측 대체·스케일링·인코딩·피처 선택·리샘플링은 train에서만 학습한다. 교차 검증 때도 각 fold의 train에서 수행한다. 학습된 처리는 validation/test에 적용만 한다.
- 모델·피처·임계값·하이퍼파라미터 선택은 validation 또는 train 내부 CV로 한다. test 결과를 보면서 반복 조정하지 않는다.

scikit-learn을 사용한다면 [Pipeline 및 데이터 누수 안내](https://scikit-learn.org/stable/common_pitfalls.html)를 따른다. 분할 자체의 그룹·시간 누수는 Pipeline만으로 해결되지 않으므로 별도로 확인한다.

## 4. 베이스라인과 비교 실험

간단한 기준 모델부터 실제 실행해 비교 기준을 만든다. 이후 서로 다른 알고리즘을 동일 조건에서 비교한다. 단순한 상수 예측 기준만으로 수업의 ‘알고리즘 2개 이상 비교’를 충족했다고 간주하지 않는다.

실험마다 가설과 바꾼 조건을 기록한다. 공통 분할·데이터 버전·지표를 고정하고, 하이퍼파라미터 탐색 범위와 선택 기준을 남긴다. 실패하거나 성능이 낮은 실험도 이유를 기록한다.

seed는 분할·모델·샘플링 등 무작위 연산에 적용하고 저장한다. 특정 seed의 좋은 점수만 골라 보고하지 않는다. 필요하면 여러 seed의 변동성을 확인한다. 하드웨어·패키지 차이에 따른 재현 한계도 기록한다.

## 5. 평가와 시각화

분류/회귀 유형과 불균형·오류 비용에 맞는 지표를 고른다. 지표 이름만 쓰지 말고 집계 방식, 양성 클래스, 단위, 임계값, 좋은 방향을 정의한다. 예를 들어 F1의 macro/weighted, ROC-AUC의 확률 입력, RMSE의 목표 단위를 구분한다.

평가셋과 표본 수를 표시한다. 학습 점수를 최종 일반화 성능처럼 쓰지 않는다. 모델을 확정한 뒤 test를 최종 평가에 사용하고, 이후 설계를 바꿨다면 독립적인 최종 평가가 약해졌음을 기록한다.

그림은 실제 데이터·실험 결과에서 생성한다. 축·범례·단위·대상 집합을 명시하고, 선택한 모델과 비교한 모델을 공정하게 표시한다. 결과·그림을 손으로 고쳐 성능이 달라 보이게 만들지 않는다.

## 6. 실행 기록과 노트북

실행 ID별 기록 항목은 [공통 기준](CONTRACTS.md)에 따른다. 새 실험은 새 ID로 남겨 기존 결과를 덮어쓰지 않는다. 결과가 없다면 ‘미실행’, 일부만 돌렸다면 ‘부분 실행’으로 표시한다.

노트북은 커널을 재시작해 위에서 아래로 실행한다. 숨겨진 변수, 개인 경로, 이전 실행의 출력에 의존하지 않도록 한다. 의존성과 실제 실행 순서를 README에 기록한다. 민감하거나 과도하게 큰 출력은 커밋하지 않는다.

## 7. 변경별 확인 범위

| 변경 | 확인할 내용 |
| --- | --- |
| 문서 | 링크·파일 경로·현재 상태·실행 예시의 정확성 |
| 데이터 로딩·전처리 | 작은 입력에서 자료형·누락값·중복·타깃 분리·행 ID 유지 |
| 분할 | 그룹/시간 조건과 집합 중복 여부, 모든 비교 모델의 동일 분할 |
| 학습·평가 | train에만 fit, 공통 지표 정의, 예상 가능한 작은 예제의 지표값 |
| 결과·그래프 | 실행 기록과 값 일치, 축·단위·평가셋 표시 |
| 최종 제출 | 새 환경에서 재실행, 필요한 데이터와 환경 안내, 실제 산출물 연결 |

검증 수단과 실행 명령은 코드가 생기면 확정한다. 현재 테스트 도구나 통과한 테스트가 있다는 뜻은 아니다.
